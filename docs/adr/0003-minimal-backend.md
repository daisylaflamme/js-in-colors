# 0003. Minimal backend in version 1

- Status: Accepted (amended by [0012](0012-ask-dot-live-mode.md): the chat proxy is plain HTTP streaming, not GraphQL; and by [0015](0015-no-graphql-or-d3-in-version-1.md): no GraphQL client or MSW in version 1)
- Date: 2026-11-02

## Context

This is a front-end portfolio project. Its value is in the Angular app, the design system, accessibility, animation, and tests. A real backend (database, auth, hosting, migrations) would take time away from that and add privacy risk (see [0001](0001-anonymous-first-local-first-progress.md)).

Still, the app should be built the way a real product is: it talks to an API through a typed client, and swapping the fake API for a real one later should not touch components.

## Decision

- **No database, no Python, no real auth in version 1.**
- **The client speaks GraphQL** (Apollo Angular, with types generated by graphql-codegen from a schema in `libs/shared`).
- **The API is mocked with MSW** (Mock Service Worker) in development and in Cypress. The handlers live in `libs/data-access`. Lesson content is static data (YAML in `content/lessons`), so most screens need no server at all.
- **One tiny server, only if needed:** a TypeScript GraphQL Yoga app in `apps/api`, used for the AI chat proxy (keys must never reach the browser) and later the resume-code sync. In demo mode the chat returns canned, kid-safe answers.
- Postgres and a real API are optional later milestones, each with its own ADR.

## Consequences

- The app can be deployed as static files. Every feature works offline after the first load, except chat.
- The GraphQL schema is the contract. MSW handlers and a future real server implement the same schema, so components and stores do not change when the backend does.
- Mocks can drift from reality. Generated types and contract tests against the schema keep that in check.
- The scaffold does not include GraphQL, MSW or `apps/api` yet. They are added with the first feature that needs them.
